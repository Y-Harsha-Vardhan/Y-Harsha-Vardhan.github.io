Restaurant E-Commerce Platform

A small full-stack restaurant ordering app built as a team project. Menu browsing, cart, checkout, and an admin dashboard for managing items — implemented with a vanilla JavaScript frontend and modular page-level structure.

2024 HTML · CSS · JavaScript Team project

What it does

The user-facing flow is the standard food-ordering loop: browse the menu, add items to a cart, review and adjust quantities, place an order. A separate admin view exposes the operations side — manage menu items, view incoming orders, change prices and availability.

Structure

The codebase is organised around discrete screens rather than a single-page-app bundler. Roughly half the lines are CSS — most of the visual identity (restaurant theme, food cards, hero imagery) lives there. The "Penthouse" folder suggests a themed section or premium tier within the menu.

My contribution

This was a collaborative project; my work focused on the frontend interaction layer — cart state management, checkout transitions, and menu rendering. The repo is hosted under a teammate's account.

What I'd carry forward

The exercise made the case for state libraries — even at this small scale, a cart that lives across pages and survives reloads quickly becomes the kind of thing where ad-hoc localStorage reads and writes turn into bugs. A rebuild today would start with a clear single source of truth for cart state and treat the UI as a derived view of it.
