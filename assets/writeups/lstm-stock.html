Stock Price Prediction with LSTM

A time-series forecasting pipeline built in TensorFlow/Keras: pulls historical OHLCV data with yfinance, augments it with technical indicators, trains a stacked LSTM on a 60-day sliding window, and forecasts adjusted closing prices for the next 15 trading days.

Summer 2025 Python · TensorFlow / Keras yfinance · pandas · sklearn

Pipeline

The script is interactive — it asks for a ticker and a date range, fetches daily candles via yfinance, and runs a five-stage pipeline: feature engineering → preprocessing → model build → train → forecast.

Features

Rather than feeding raw close prices, the model takes three channels:

  • Adjusted Close — the target signal, scaled.
  • MACD — 12/26-period EMA difference plus a 9-period signal line, a momentum/trend indicator.
  • RSI(14) — relative strength index, oscillating 0–100; overbought above 70, oversold below 30.

Adding technical indicators alongside the price gives the network more context than the price series alone — momentum and overbought/oversold information are visible in the input rather than requiring the network to learn them from scratch.

Preprocessing

All three features are MinMaxScaler-normalised to [0, 1]. A sliding window of 60 days is used to predict the next day's adjusted close — so each training sample has shape (60, 3). An 80/20 chronological train/test split avoids the obvious sin of randomly shuffling time-series data.

Model

Stacked LSTM in Keras:

  • LSTM(50, return_sequences=True) → Dropout(0.2)
  • LSTM(50) → Dropout(0.2)
  • Dense(25) → Dense(1)

Optimised with Adam against MSE, trained for 25 epochs at batch size 32. Evaluated on the held-out 20% with the R² score.

Forecasting beyond the training range

For the 15-day forward forecast, the last known 60-day window is fed in, the next scaled price is predicted, and that prediction is appended to the window — sliding forward one day at a time. There's a deliberate simplification here: the MACD and RSI for synthetic future days are held at their last known values rather than recomputed (recomputing them from a predicted price compounds error fast). This is called out in the code as a known approximation.

What I'd carry forward

The model trains cleanly, but forecasting financial time series with an LSTM is humbling — R² on the test set is much friendlier than performance on truly out-of- sample data. The real takeaway was the shape of the pipeline: feature engineering > model choice, scaling and windowing matter, and recursive forecasting compounds errors quickly. Useful scaffolding to extend with attention, transformers, or proper walk-forward validation.
