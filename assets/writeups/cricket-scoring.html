Cricket Scoring System

A browser-based live cricket scoring app, built end-to-end as a CS104 course project. Five screens — setup, live scoring, scorecard, summary, plus a Python autofill utility — wired together by a single JavaScript scoring engine that handles the cricket-specific rules (overs, wides, no-balls, wickets).

IIT Bombay · 2024 HTML · CSS · JavaScript Python (autofill)

Screens

The app is structured as a sequence of static pages with shared client-side state:

  • Setup (setup.html) — team names, players, toss, match format.
  • Live scoring (live.html) — the active scorer's interface, ball-by-ball entry.
  • Scorecard (scorecard.html) — the broadcast-style view, with batter/bowler stats and fall-of-wickets.
  • Summary (summary.html) — post-match digest.

Scoring engine

score.js is the core: it maintains innings state and applies the rules of cricket on each delivery. The non-obvious parts are the ones that look trivial until you build them:

  • An over isn't always six legal balls — wides and no-balls don't count, and the ball-counter must roll over to the next over only after the sixth legal delivery.
  • A wicket changes the active batter; the strike rotation must follow the runs scored on that delivery.
  • The bowler rotates at the end of each completed over and can't bowl two in a row — a small piece of state with surprising downstream consequences.

Autofill

autofill.py generates realistic match scenarios for testing the UI without manually entering hundreds of deliveries. Useful for catching edge cases — last-ball wickets, super-overs, declared innings — that would otherwise need patient hand-entry.

What I'd carry forward

The biggest lesson was about state — most of the bugs were not in the UI or the layout, they were in transitions between innings, between overs, between batters. Building rules-engines for any sport teaches you that the rules you "know" leave out half of the edge cases.
